# DEPLOYMENT — публікація та встановлення

Застосунок — статична PWA без backend. Хостинг віддає лише HTML/CSS/JS/іконки/
service worker. **Фінансові дані нікуди не надсилаються** — вони живуть у
IndexedDB браузера/встановленої PWA.

## Стан публікації

На момент підготовки середовище **не авторизоване в GitHub** (немає `gh` CLI та
git remote), тому фактична публікація **не виконувалася**. Нижче — усе потрібне,
щоб опублікувати за один прохід. Публічний URL з'явиться після кроків нижче й
має бути вписаний сюди та в `RUN_STATUS.md`.

`Публічний URL: <заповнити після публікації>`

## Автоматична публікація (GitHub Pages + Actions)

Workflow: `.github/workflows/deploy-pages.yml`. Він на кожен push у `main`/`master`:
1. `npm ci`;
2. обчислює base path з імені репозиторію (user-site → `/`, інакше `/<repo>/`);
3. `npm run typecheck` та `npm test`;
4. `npm run build:pages` з `VITE_BASE_PATH`;
5. перевіряє PWA-артефакти (`scripts/check-pwa.mjs`);
6. викладає `dist` на GitHub Pages.

### Один раз налаштувати

```bash
./scripts/setup-github-pages.sh <github-username> <repo-name>
git push -u origin main
```

Потім у GitHub: **Settings → Pages → Source: GitHub Actions**.

Публічна адреса: `https://<username>.github.io/<repo>/`
(для репозиторію виду `<username>.github.io` — просто `https://<username>.github.io/`).

## Як змінити ім'я репозиторію або base path

Base path ніде не хардкодиться. Він визначається `VITE_BASE_PATH` (єдиний
механізм). Локально:

```bash
VITE_BASE_PATH=/new-name/ npm run build:pages
```

У CI ім'я береться автоматично з репозиторію — достатньо перейменувати репозиторій.

## Альтернатива: Netlify Drop / Cloudflare Pages

1. `npm run build` (base `/`, для кореня домену).
2. Netlify Drop: перетягніть теку `dist` на <https://app.netlify.com/drop>.
3. Cloudflare Pages: «Direct Upload» → завантажте `dist`.

Для підпапкового хостингу зберіть із відповідним `VITE_BASE_PATH`.

## Як відкотити публікацію

- GitHub Pages: у розділі **Actions** повторно запустіть попередній успішний
  workflow (`Re-run jobs`), або зробіть `git revert` проблемного коміту й push.
- Повне вимкнення: **Settings → Pages → Source: None**.

## Як переконатися, що дані не йдуть на сервер

- У коді немає жодного `fetch`/`XMLHttpRequest`/WebSocket до зовнішніх адрес для
  фінансових даних (перевірка: `grep -rn "fetch(\|axios\|XMLHttpRequest" src` —
  нічого, окрім реєстрації SW).
- Немає аналітики/трекерів.
- У DevTools → Network під час роботи немає вихідних запитів з даними (лише
  завантаження статики й service worker).
- Експорт створює локальний файл через `Blob` + `URL.createObjectURL` — нічого не
  надсилається.

## Встановлення на iPhone (Safari)

1. Відкрийте застосунок у Safari.
2. Меню «Поділитися» (квадрат зі стрілкою) → «На екран “Початковий”».
3. Запускайте з іконки на домашньому екрані (працює офлайн).

## Встановлення на Android (Chrome)

1. Відкрийте застосунок у Chrome.
2. Меню (⋮) → «Встановити застосунок» (або банер встановлення).
3. Запускайте з іконки (працює офлайн).

## Встановлення на Mac

- Chrome/Edge: значок встановлення у рядку адреси → «Встановити».
- Safari: «Файл → Додати до Dock» (новіші версії macOS).

## Оновлення застосунку

- Нова версія кешується service worker'ом. З'являється банер «Доступна нова
  версія» → кнопка «Оновити» застосовує оновлення та перезапускає оболонку.
- **Оновлення не очищає IndexedDB** — усі фінансові дані зберігаються.

## Резервна копія

- Налаштування → «Експортувати дані» → файл `budget-backup-YYYY-MM-DD-HHmm.json`.
- Зберігайте копію поза пристроєм (хмара/пошта на власний розсуд користувача —
  застосунок нічого не надсилає сам).

## Видалення локальних даних

- Налаштування → «Небезпечна зона» → «Очистити всі дані» (подвійне підтвердження).
- Або очищення даних сайту в браузері (видалить усю статистику).
