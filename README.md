# Мій бюджет — локальний застосунок особистого бюджету

Mobile-first PWA для планування місячного бюджету, обліку витрат і фінансової
грамотності. Працює **повністю локально** — без сервера, реєстрації та хмари.
Усі фінансові дані зберігаються в IndexedDB на вашому пристрої.

Мова інтерфейсу — **українська** (архітектура готова до ru/en).

## Призначення

Застосунок веде вас через реальний місячний цикл бюджету:

> Фактично прийшла зарплата → ви вводите точну суму → застосунок аналізує
> минулі місяці → пропонує план по категоріях → ви коригуєте й підтверджуєте →
> місяць стає активним → ви записуєте доходи й витрати → застосунок перераховує
> залишки → при нестачі фіксується джерело компенсації → ви закриваєте місяць →
> отримуєте підсумок і рекомендації → наступний місяць отримує точніший бюджет.

Ключові принципи:

- Гроші рахуються **в цілих копійках** (без float-помилок).
- Резерв, накопичення, розподілені та вільні гроші **не змішуються**.
- Рекомендації **пояснювані** (без ШІ), фінальне рішення завжди за користувачем.
- Критичні категорії (ліки, оренда, комуналка) захищені від автоскорочення.

## Встановлення

```bash
npm install
```

## Запуск (dev)

```bash
npm run dev
```

Відкрийте http://localhost:5173 (порт може відрізнятися).

## Збірка (production + PWA)

```bash
npm run build
npm run preview
```

`vite-plugin-pwa` генерує service worker і manifest — після першого відкриття
застосунок працює офлайн і встановлюється як PWA.

## Тести

```bash
npm test          # unit + integration (Vitest)
npm run typecheck # перевірка типів
npm run lint      # ESLint
npm run test:e2e  # Playwright E2E (спершу: npx playwright install)
```

## Структура проєкту

```
src/
  app/            App.tsx, роутінг, нижня навігація
  components/     UI-компоненти (Sheet, ExpenseSheet, TransferSheet, ...)
  pages/          Екрани: Home, Operations, Budget, Reports, Settings
  features/
    months/       Майстер створення місяця, закриття місяця
    backup/        Експорт/імпорт JSON, демо-дані
  domain/
    money.ts      Грошовий тип (цілі копійки)
    models.ts     Доменні моделі
    validation.ts Zod-схеми
    calculations/ balances.ts, recommendations.ts (чисті функції)
  db/             Dexie-схема, репозиторії, сервісний шар, seed
  hooks/          useDb (live queries), useFormat
  i18n/           Централізовані переклади

  tests/          Vitest unit + integration

```

## Експорт та імпорт (резервні копії)

Оскільки сервера немає, резервні копії критично важливі. У **Налаштуваннях**:

- **Експортувати дані** → файл `budget-backup-YYYY-MM-DD-HHmm.json`.
- **Імпортувати дані** → перевірка через Zod, попередній перегляд, режими
  «Замінити» / «Об’єднати». Перед імпортом автоматично зберігається копія
  поточної бази.

## Публікація (GitHub Pages)

Статична PWA публікується через GitHub Actions (`.github/workflows/deploy-pages.yml`).
Base path обчислюється автоматично з імені репозиторію (`VITE_BASE_PATH`), нічого
хардкодити не треба. Разова підготовка:

```bash
./scripts/setup-github-pages.sh <github-username> <repo-name>
git push -u origin main
```

Потім увімкніть **Settings → Pages → Source: GitHub Actions**. Деталі, альтернативи
(Netlify/Cloudflare), встановлення на iPhone/Android/Mac, оновлення й відкат — у
[DEPLOYMENT.md](DEPLOYMENT.md).

**Публічний URL:** 👉 https://deusrat-lab.github.io/campaign-timeline-vtt/
(інструкція встановлення на телефон — [INSTALL_ON_PHONE.md](INSTALL_ON_PHONE.md))

> Публікація виконана методом **deploy-from-branch** (гілка `gh-pages`), бо
> доступний токен має scope `repo` без `workflow`. Готовий Actions-workflow —
> у `docs/ci/` як референс.

## PWA

- `display: standalone`, portrait, тема під світлий/темний режим.
- Офлайн-кеш через Workbox, `navigateFallback` на `index.html`.
- `viewport-fit=cover`, підтримка safe-area (Dynamic Island, нижній жест-бар).
- Оновлення застосунку не видаляє дані користувача.

## Обмеження локального зберігання

⚠️ Дані живуть у IndexedDB цього браузера/пристрою. **Очищення даних сайту у
браузері видалить статистику.** Кожен пристрій має власну незалежну базу.
Регулярно робіть експорт. Синхронізації між пристроями поки немає — але
доменна модель спроєктована так, щоб її можна було додати без переписування.
