## Ручна browser-перевірка (виконано цього прогону)

Через dev-сервер (`npm run dev`), повний сценарій:
1. Створено місяць, дохід 60 000 ₴, план «Ліки» 3 200 ₴, активовано місяць.
2. Тижнева картка одразу показала коректні цифри (не `/4`): «Безпечний
   бюджет 2 608,70 ₴» при 23 днях місяця / 1 дні поточного тижня.
3. Додано витрату 3 500 ₴ на «Ліки» через пошук категорії в `ExpenseSheet` →
   статус картки «Перевитрата», дефіцит 300 ₴.
4. «Покрити дефіцит» → `TransferSheet` відкрився з сумою 300 і категорією
   призначення вже вибраними → підтверджено → дефіцит 0, `TotalExpense` і
   `ActualCashBalance` не змінились (перевірено по цифрах на екрані).
5. Сторінка «Операції»: тап по операції «Ліки» → аркуш редагування → сума
   3500 → 2000 → Зберегти → рядок в списку оновився на 2000 ₴ **без**
   дублювання (кількість операцій не змінилась).
6. Сторінка «Бюджет»: категорія «Ліки» одразу показала «Факт: 2 000,00 ₴»,
   статус «В нормі», з'явилась дія «Перерозподілити залишок» — усе без
   перезавантаження сторінки (Dexie `useLiveQuery` реактивність).
7. Сторінка «Підсумки»: live-секція «Цей місяць (live)» показує актуальні
   підсумки одразу, без закриття місяця.

## Знайдена й виправлена проблема цього прогону

Під час верифікації в браузері виявлено, що dev-сервер підвантажував **старі
скомпільовані `.js`-файли**, які випадково опинились у `src/` поряд з
реальними `.tsx`/`.ts` (наслідок баг у скрипті `npm run typecheck`, який
викликав `tsc -b --noEmit false` без `outDir` — TS емітив `.js` прямо в
`src/`, а Vite резолвив їх замість джерел). Це повністю ховало всі UI-зміни
цього релізу в dev-режимі (хоча build і тести залишались коректними, бо вони
працюють з `.tsx` напряму). Виправлено:
- видалено 44 застарілих `.js`-файли (вони були untracked, нічого не
  втрачено);
- скрипт `typecheck` змінено на `tsc -b` (без небезпечного `--noEmit false`
  override) — тепер він не може повторно згенерувати цю проблему.
